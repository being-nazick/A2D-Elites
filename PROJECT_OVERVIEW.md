# Project Overview: My Dairy App

This document provides a breakdown of the workspace structure and explains the purpose of each part of the application, focusing on key requested files. The project is a React-based web application configured with Capacitor to run natively on Android.

## Detailed File Breakdown

Here is what each specific core file and component does within the context of the application:

### `src/App.js`
The primary entry point and central container for the React application. It likely maintains the top-level application state, orchestrates routing/navigation between different tabs (like Dashboard and Orders), and imports shared UI layout elements (like `SharedAppHeader`, `SharedBottomNav`, `SharedTopBar`).

### `src/app/constants.js`
Stores global constants and configuration values. This includes theme color palettes (`LIGHT` and `DARK`), typography (fonts), business details (name, address, contact, UPI info), default product lists (like Milk, Paneer, Curd with their prices), and categories with matching emoji icons. 

### `src/app/helpers.js`
Contains various pure utility and helper functions used throughout the application. It includes logic for generating unique IDs, formatting dates and currency (INR), calculating order totals and amounts due, checking for valid coordinates, and generating external links to WhatsApp and Google Maps for customer navigation.

### `src/app/storage.js`
Provides a custom React hook `useCapacitorStorage` that interfaces with `@capacitor/preferences`. This hook simplifies reading from and writing to persistent local storage on the device, allowing the app to seamlessly save and load user preferences or application state asynchronously.

### `src/features/dashboard/Dashboard.js`
The main dashboard view component. It typically presents high-level statistics, aggregations, and business metrics to the user at a glance. It might use libraries like `recharts` to render visual data summaries.

### `src/features/orders/OrdersTab.js`
A major view component responsible for managing the orders section. It likely handles displaying a list of current and past orders, managing filtering, and allowing the user to interact with the order data (viewing, editing, or settling payments).

### `src/features/invoiceService.js`
A dedicated service module handling the business logic for creating and formatting invoices. It encapsulates the process of taking order data and generating a structured invoice document, potentially exporting it to PDF utilizing `html2pdf.js`.

### `src/components/Shared.js`
Acts as a central export hub or repository for common, reusable, smaller UI components and styled elements. Examples include `AppHeader`, `BottomNav`, `TopBar`, `Chip`, `QtyLine`, and `StatusPill`. By centralizing them here, it makes importing these components cleaner across the app.

### `src/components/OrderRow.jsx`
A specific presentation component used to render a single row or item within an orders list or table. It handles the UI layout for an individual order's details (like customer name, total amount, status) to ensure consistency across the application.

### `src/components/LocationPicker.js`
A map-based UI component (built using `react-leaflet`) that provides an interactive interface for users to select or view geographic locations, presumably for customer addresses and delivery routing.

## General Structure

*   **`android/`**: Contains the native Android project structure generated by Capacitor.
*   **`public/`**: Static assets that are served directly by the web server (e.g., `index.html`, manifest files).
*   **`package.json`**: Defines the project dependencies (React, Capacitor, Leaflet, Recharts, html2pdf.js, etc.) and npm scripts.
